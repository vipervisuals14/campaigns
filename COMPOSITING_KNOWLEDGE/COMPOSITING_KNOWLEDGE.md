# Compositing Knowledge

General, cross-project working principles. Keep shoot-specific observations in each `PROJECTS/PROJECT_NNN/Project_Notes.md`.

## Operating principles

- Inspect the current branch, repository tree, knowledge files, project notes and approved references before starting a new shoot.
- Preserve source photographs. Work non-destructively, keep originals byte-for-byte, and produce composites as separate working files.
- The subject should remain the original photographed person. Use a careful matte and compositing workflow; do not synthesize or reinterpret the subject.
- Analyze each capture independently. A shared shoot does not imply a shared camera position, lens, horizon or background plate.
- Treat unreviewed output as a draft. Never list a draft as approved until the user explicitly approves it.
- Ask specific questions when a missing reference or technical ambiguity could compromise realism.
- Store global standards here and technical methods in `TECHNIQUES/`; keep facts and corrections tied to a shoot in project notes/history.

## Knowledge-base maintenance

At project start, read this file, `MASTER_INSTRUCTIONS.md`, `VISUAL_STANDARDS.md`, `APPROVED_REFERENCES.md`, `CORRECTIONS_LOG.md`, `PROJECT_HISTORY.md`, relevant technique notes and the relevant project notes. After a meaningful correction or approval, update the relevant files, verify the Git diff, commit to the active Arena branch and push only that branch. Never say a knowledge update is saved until the push succeeds. Preserve prior approved reference files; add new versions rather than overwriting them.
